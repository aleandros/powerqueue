Your Claude subscription,
working all week,
on one cheap VPS.

powerqueue turns your Linear queue into autonomous Claude Code sessions and keeps them running around the clock. It paces them so the whole weekly allowance goes to the work that matters, with fable held for what is critical. Add a Codex or Google subscription and it spreads the queue across all of them, each paced against its own budget. It needs nothing but the subscriptions you already pay for and a small box that stays on, or your laptop.

› why it's cheap

    
Most of a Claude subscription goes unused: the 5-hour windows reset while you sleep and the best model sits idle until something urgent lands. powerqueue spends that capacity for you and stops at the limit, so the bill is what you already pay. Already paying for Codex or Google AI Pro too? Those allowances join the same queue.

    

      

        
the subscription you have

        
Sessions run through your normal Claude Code login, so usage counts against Pro or Max, not an API account. No per-token bills, no keys to rotate.

        
# budget pacing, per tier, per week
fable   held for critical work
opus    high-priority tickets
sonnet  everything else, all week

      

      

        
one small box

        
The daemon only runs git, tmux and Claude Code. A VPS with a couple of gigabytes of RAM runs several sessions side by side. Your laptop works just as well while it is open.

        
ssh box
claude                  # log in once
powerqueue init --permission-mode auto
powerqueue run          # or a systemd unit

      

      

        
nothing else

        
One static binary, SQLite, a Markdown rules file. No orchestration platform, no cloud account, no agents-as-a-service. Linear is optional: powerqueue add queues work by hand.

        
$ powerqueue budget show
period  43% used, day 3.1 of 7
window  12% of the 5h window
fable   8% of 25% share, 12 tasks ok

      

    

  






  

    
› how it works

    


  Linear ──poll──▶ queue ──PRIORITY.md──▶ score ──budget policy──▶ pick model
                                                                        │
  tmux window ◀── claude --session-id … ◀── launch.sh ◀── git worktree ◀┘
       │
       ├─ hooks ──▶ powerqueue hook ──▶ SQLite ──▶ daemon tick
       ├─ transcript.jsonl ──▶ token usage (per model)      ├─ crash?  → backoff, --resume
       └─ /proc ──▶ CPU, RSS                               ├─ idle?   → nudge, needs_attention
                                                            └─ done?   → push, clean up, Linear → In Review

    

    

      
1. syncQueued issues from your team become tasks. Manual tasks come from powerqueue add.

      
2. scoreRules in a Markdown file set criticality and score. Edit it; the daemon reloads live. Optional Jev scoring.

      
3. pick a modelThe budget policy chooses the best tier the period and the 5-hour window can afford.

      
4. runA fresh worktree, a tmux window, an interactive Claude Code session you can attach to at any time.

      
5. watchHooks report turns, prompts and failures. Transcripts give tokens. A dead pane means a resumed retry.

      
6. finishClaude runs powerqueue task complete; the branch is pushed, the worktree removed, Linear updated.

› get it running


    

      

        
one-liner

        
Detects OS + architecture, drops the binary in /usr/local/bin (or ~/.local/bin). Run it again to update.

        
curl -fsSL https://raw.githubusercontent.com/aleandros/powerqueue/main/install.sh | sh

      

      

        
cargo

        
Rust toolchain required. Builds the latest main.

        
cargo install --git https://github.com/aleandros/powerqueue

      

      

        
pinned

        
Pin a release or pick the install directory with environment variables.

        
POWERQUEUE_VERSION=v0.3.0 \
POWERQUEUE_INSTALL_DIR=~/bin \
  sh -c "$(curl -fsSL https://raw.githubusercontent.com/aleandros/powerqueue/main/install.sh)"

      

    


    

      
then use it

      

        
# guided setup: Linear key → keychain, team, states, permission mode, PRIORITY.md
powerqueue init

# check tools, keys, state and the algorithm
powerqueue doctor

# start the scheduler (keep it in a tmux window or a service)
powerqueue run

# watch sessions, budget and the queue
powerqueue dashboard

# jump into a task's session, or queue something by hand
powerqueue attach ENG-412
powerqueue add "Rotate the staging certs" --criticality high

      

    

  






  

    
› rules and budget

    

      

        
PRIORITY.md

        
Criticality comes from the first matching section. Scoring lines add points. Overrides pin a ticket. ## Models states a preference the budget may downgrade. Save the file and the daemon re-scores the queue.

        
## Critical
- label: incident
- priority: urgent and label: customer

## Low
- label: chore

## Scoring
- +40 if label: customer
- -30 if estimate > 8

## Overrides
- ENG-412: critical
- ENG-377: skip

## Models
- critical: fable
- high: opus
- normal: sonnet

      

      

        
budget policy

        
Each tier gets a share of the period's weighted tokens and a minimum criticality. Early in the week only critical work touches Fable. Once a tier is under-paced it relaxes one level; in the end game it opens up so nothing is wasted. A rate_limit pauses every tier until the cooldown.

        
# config.toml
[budget]
period_hours = 168
window_hours = 5
period_weighted_tokens = 80_000_000
endgame_fraction = 0.8

[budget.models.fable]
share = 0.25
min_criticality = "critical"
relax_after_fraction = 0.5

[budget.models.opus]
share = 0.35
min_criticality = "high"
relax_after_fraction = 0.3

        
Calibrate with what /usage shows: powerqueue budget set-reset "in 3d4h" and powerqueue budget set-observed 43%. doctor says when Fable is over- or under-reserved.

      

    

  






  

    
› why

    

      

        Claude Code is great at a ticket, and you are already paying for far more tickets than you run. The chore is everything around them: the worktree, the window, noticing the session died, remembering which model you can still afford this week, cleaning up, moving the issue.
      

      

        powerqueue does the chore on a box that never sleeps. You keep attach, answer, review, and come back to pushed branches.
      

    

    

      Scope. Sessions are interactive so you can always attach, which means a permission prompt waits for you (the task goes to needs_attention). For a VPS that nobody watches pick the auto permission mode in init (or bypassPermissions), or pre-approve commands in claude.allowed_tools; change it later with powerqueue config set claude.permission_mode auto. Linear is the only tracker today — PRs welcome.
